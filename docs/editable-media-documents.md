# Editable media documents

The normal image Save action retains source image bytes and a versioned scene, instead of baking every edit into a progressively resized image. `editable-media-v1.js` writes a bounded PNG display preview with a private, CRC-checked `qbED` ancillary chunk. The chunk contains a JSON manifest and binary assets. The whole file, including its sources, must fit the existing 100 MiB limit. Existing Storage MIME rules and ownership checks continue to apply; there is no new public bucket or permissive RLS policy.

The editable scene is authoritative. Its base image, ink paths, text, shapes, image placements, source crop rectangles, document crop origin and reset scene survive reopening. The PNG preview is only for thumbnails and compatibility with ordinary image viewers. The enlarged in-app viewer fetches the saved file and paints source assets and scene objects onto a viewport-sized canvas at the current zoom. Preview errors retry the same edited file, never the pre-edit original.

Recent-file copies, library registrations and attachments copy complete file bytes into new object paths. Scene edits create another new file and use existing conditional row/revision updates. Nested edited images are retained as independent documents; selecting one and choosing “選択画像を編集” opens its own objects. Resetting or cropping that copy does not change its source. Whole-image and selected-image crop operations have separate buttons. Cancel does not write storage. Failed saves keep the editor open.

Existing images that were already flattened retain their current pixels and original-image links. Historical individual strokes cannot be reconstructed from pixels. Their full reset is available inside the editor, with a save required to persist it. New saves preserve editable objects. Undo/redo is per editing session; objects and reversible crops survive sessions.

PNG/PDF export is explicit and separate from normal editable-image Save. PDF export embeds PNG/JPEG source pixels without downsampling; other supported image formats are converted to lossless PNG. Pen paths and shapes are PDF vectors. Japanese text and counter labels are rendered separately as high-resolution transparent glyph images; the entire page is never rasterized for these exports.

The PDF editor retains its original PDF and per-page editable overlays in `qb-page-edits-v1.json`. It draws overlays onto the original page coordinate system, including rotated pages. New PDFs can start from a white/charcoal blank page (A4 portrait/landscape or custom dimensions), selected image/PDF files, or pasted image/PDF clipboard data. Each image becomes one page and imported PDFs contribute all pages in order. A single imported app PDF keeps its embedded editable record. Blank pages, images and PDFs can also be added after opening. Page canvases have no whole-page crop. Inserted images retain their own crop/edit actions. The in-app PDF and downloadable file show the same saved composition.

Multiple-file library registration shows the ordered inputs before storage writes. The user chooses separate cards or one card containing the selected files. PDF pages remain inside their PDF; one PDF is one file. Existing card membership remains readable. File paste works when the browser exposes PDF/image File or MIME data; OS clipboard entries unavailable to browser APIs require the file chooser. The UI explains this fallback.

Choice feedback reflects answer-key membership: correct choices green, selected incorrect choices red, other choices neutral. Review-only mode has no selected-wrong state. Registered correction text appears inside its choice after answer/review, and resets with retry/navigation. Missing correction text has no placeholder. Statement truth remains in the data and does not determine grading colors.

Verification includes original byte equality after multiple saves, crop restoration, nested-copy isolation, source-resolution zoom and editor return, PDF image dimensions and rendered pixels, blank and image-based multipage creation/reopening, contextual photo duplicate/paste actions, choice corrections/reset, and existing Chromium/WebKit library/editor/refresh regressions. Actual iPad hardware, OS clipboard delivery and a live 100 MiB upload are separate device/network checks.
