# 問題文の直接編集（手動保存）

「問題文のポイント」の直接編集エンジンを、問題文にも共通利用する。選択肢解説・試験用まとめ等の編集方式は今回は変更しない。

## 操作

- 「問題文を編集」で、表示中の `.qtext` 内が直接編集領域になる。別のtextareaやプレビューを下に作らない。
- B=太字、U=下線、S=取り消し線、M=マーカー、A=強調色。ボタン自体で書式を表現する。通常文字は本文色、マーカー背景・Aはシステムカラー。
- Cmd/Ctrl+B、Cmd/Ctrl+U、Cmd/Ctrl+Shift+S/M/A。保存は保存ボタンまたはCmd/Ctrl+S。自動保存はしない。
- キャンセルは未保存の本文・装飾を元へ戻す。未保存の移動・他欄への編集切替は確認する。保存失敗・競合では下書きを残す。空の問題文は保存しない。

## データ保護

保存対象は `questions.stem` と既存の `questions.stem_formatting` のみ。HTMLを本文へ保存しない。元の空白・改行も維持し、装飾のみなら本文を変えない。年度別 `question_occurrences.exact_stem`、公式解答、選択肢、解答欄設定、解説、学習履歴、個人メモは書き換えない。

開始時にDBから本文・装飾を読み直し、管理者権限と問題IDを確認する。保存時も本文・当該装飾・アカウントの競合を確認し、`updated_at` 条件付きで更新する。今回のリリースにDBマイグレーションや既存問題の一括更新はない。

未保存の問題文は問題識別に使わない。既存の問題識別処理から、編集中の同一DOMノードに結び付けた確認済みIDを参照する。別問題への描画切替後はこの参照を使用しない。文字入力ごとに問題変更イベントを発生させない。

## 画像・個人メモ

問題画像は同じ場所に残す。「画像を編集・追加」は既存の問題画像管理コントロールを開く。画像追加の処理は新設せず、ファイル・貼り付け・最近の画像等の既存機能を利用する。既存ライトボックスの対象に `.qsiImg` を追加し、問題画像も拡大できるようにする。

画像操作は本文と独立して反映される。本文のキャンセルでは保存済みの画像操作を戻さない。この注意を編集画面に表示する。個人メモと画像は従来の保存処理・表示場所を維持する。

## 検証・退避

`tests/inline-stem.browser.cjs` は実際の問題ID判定・問題画像管理・固定メニューバーを読み込み、合成DB/Auth/Storageで検証する。本番へのテスト書き込みは行わない。既存の装飾・全体解説・記述のテストも引き続き実行する。iPhone実機の日本語入力・外付けキーボード操作は別途確認が必要。

`?editor=classic` で従来編集へ戻す診断経路を維持する。手動保存の安定確認前に自動保存へ移行しない。
