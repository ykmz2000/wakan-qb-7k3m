# 画像ライブラリ v1：非破壊の追加設計

既存のアップロード・貼り付け・最近の画像を維持し、独立した管理画面と画像選択の入口を追加する。既存の問題・画像をライブラリへ自動移行しない。入口を外しても既存機能と貼り付け済みコピーが動作する。

## 今回の範囲

- 初期公開は既存の管理者ロールのみ。閲覧・管理・公式画像への利用を含む。一般利用者への公開・個人メモへの利用は権限設計後の拡張。
- 常設入口は右上のランキングとマイページの間への追加案。下部メニューの削除・移動はしない。
- 問題文、問題文のポイント、選択肢解説、出題意図、試験用まとめ、医学的検証の既存画像操作へ「ライブラリ」を追加。
- `choice` の原選択肢画像もDB登録APIでは対応。既存画面に該当編集欄がない場合は新たな編集欄を作らない。
- 複数画像は選択した順で貼り付ける。直前の成功が通信上不明になった場合は同一リクエストIDで回復し、二重登録を防ぐ。
- 表示は文字、画像、余白、最小限の線と既存テーマ色。分類をチップ・絵文字・独自配色にしない。
- 画像操作ボタンは共通の文字サイズ・太さ・余白・テーマ色を使い、絵文字と角丸を付けない。
- ライブラリへの追加はファイル選択、コピペ、最近の画像の3経路。クリップボードを直接読み取れない端末には貼り付け欄を表示する。
- 最近の画像はライブラリ内で全科目から選択でき、現在の画像と書き込み前の画像を区別する。選択した版の実データを新規パスに保存し、元の問題画像・使用履歴は変更しない。キャンセルでは登録しない。登録時にOCR・分類は実行しない。

## 保管・履歴

| 情報 | 保存先・扱い |
|---|---|
| 原本 | 非公開 `qb-image-library` bucket。ランダムな新規パスへ書き込み、上書きしない |
| 現在の情報 | `qb_image_library_items`。画像版と情報版を別管理 |
| 情報の履歴 | `qb_image_library_history`。変更前後・変更元・日時・操作者を追記 |
| AI読み取り履歴 | `qb_image_library_readings`。OCR原文、補完後全文、図の説明、補完箇所・根拠・確実性を保存 |
| 使用履歴 | `qb_image_library_usages`。原本ID・使用時の版・コピーID・問題ID・貼り付け先 |
| 検索語辞書 | `qb_image_library_terms`、変更は `qb_image_library_term_history` に追記 |
| 停止設定 | `qb_image_library_config.enabled` |

ライブラリから使うときは原本のバイト列をダウンロードし、新しいパスへ `upsert:false` でアップロードする。保存されたコピーを確認してから `qb_library_attach` が `question_images` と使用履歴を1トランザクションで追加する。既存の画像行には触れない。この `question_images` 行が既存の「最近の画像」の対象となる。

原本を差し替えても以前の画像は残る。現在の読み取り本文・図の説明は旧画像と混ざらないようにリセットし、旧情報は履歴に残す。差し替えで分類・キーワードは引き継ぐため、必要に応じて手動修正する。コピーには反映しない。

ライブラリの削除はアーカイブ。削除一覧から復元できる。問題側画像の削除後も原本・使用履歴が残り、原本の削除後も問題側コピーが残る。「使用履歴あり」は過去の使用実績であり、現在その問題に画像が存在することとは区別する。

アップロード成功・DB登録失敗などで未登録のオブジェクトが残り得る。通信結果が不明なまま削除すると正常登録済み画像を壊すため、自動清掃は行わない。保管量の監視と、使用先・履歴・処理状況を突き合わせた清掃は別の管理作業とする。

## 複数科目・検索

`metadata` の配列項目は `subject_ids / topics / keywords / aspects / roles / aliases / related_keywords`。文章項目は `name / notes / ocr_text / visual_summary`。各項目は省略可能で、疾患名は必須ではない。

- 科目は既存の科目IDを複数持つ。主科目の指定は不要。
- `topics` は画像が中心に説明するもの。`keywords` は実際に含まれる内容。
- `roles` は総まとめ・個別解説・比較など。`aspects` は構造・機能・病態・検査など。
- 全項目と科目名を検索。画像内の本文・注記・表ラベルも、読み取り本文として保存すれば検索できる。
- タイトル・中心テーマを優先し、本文だけ一致する画像も表示。一致箇所を抜粋する。
- NFKC、英字大小、カナ表記を正規化。辞書にある読み・略語・別名は同義語として展開。
- 関連だけする語は同義語に混ぜず「関連する内容も検索する」で利用。
- 空白区切りの複数語はAND。引用符で句を指定でき、辞書に登録済みの複数語の別名は一つの検索語として扱う。
- 誤入力は候補を表示してユーザーが選ぶ。黙って検索語を置き換えない。
- 科目フィルタは選んだ科目のいずれかに一致、他のフィルタとはAND。DBで検索・絞り込み後にページ分割する。
- 生OCRの誤認識や未採用のAI案は現在の検索に混ぜない。補完後の本文・手動修正値を検索する。

これは保存済みテキストと辞書による検索であり、検索時の生成AI・画像ベクトル解析は実行しない。検索語辞書は編集可能だが、全医学用語の別名を初期収録するものではない。

## AI依頼と手動修正

アップロード・閲覧・検索・画像選択からOCR、分類、生成AI APIを呼び出さない。新規アップロードは `unprocessed + unknown` で直ちに使える。

詳細画面の「AIに依頼する・結果を取り込む」から、読み取りまたは分類の依頼文をコピーし、AIとの会話に貼り付ける。依頼文には30分だけ有効な原本URLと画像ID・画像版・情報版を含む。AIの結果を同じ詳細画面へ取り込む。アプリ内から直接モデルを実行するサーバー接続は今回追加しない。

読み取りでは画像の図・写真・表と文章の前後関係も見る。読めない文字は根拠がある範囲で補完し、推定は本文にも残す。数値・単位・否定・左右は根拠なく断定しない。補完箇所には `before / after / reason / confidence` を必須とし、確実性は `high / uncertain / unreadable`。不確かな箇所があれば解析状況は「要確認」。画像そのものを加工して文字を置き換える処理ではない。

分類依頼は読み取りや問題への貼り付けと独立。読み取りのみの結果に分類は必須でない。分類のみなら `classification` を渡す。問題への自動一括配置は実装範囲に含めず、画像選択から独立コピーを作る操作で対応する。

手動保存した項目は `manual_fields` で保護する。その後のAI値は未保護項目だけに適用し、保護項目は `ai_suggestions` に保存する。詳細で項目ごとに採用できる。手動で空にした値も保護する。手動編集とAI提案は情報版を照合し、競合時は入力を残して止める。AI連携は必ず `p_origin='ai'` のRPCを使用し、テーブルを直接UPDATEしない。

解析状況・分類状況・使用状況は別管理。未解析＋分類済み、解析済み＋分類不明、未解析＋使用済みのすべてを許す。

結果の形式例（ID・版・request_idは依頼文から引き継ぐ）：

```json
{
  "image_id": "<UUID>",
  "image_version": 1,
  "revision": 1,
  "request_id": "<UUID>",
  "reading": {
    "raw_text": "動□神経",
    "corrected_text": "動眼神経（文脈から推定）",
    "visual_summary": "図で示されている内容の説明",
    "repairs": [{"before":"動□神経","after":"動眼神経","reason":"前後の文脈と図の対応","confidence":"uncertain"}]
  }
}
```

## 公開・停止・検証

`supabase/image-library-v1.sql` を一度だけ追加マイグレーションとして適用する。既存テーブル・既存Storageポリシーは変更しない。新規表はRLS、RPCはSECURITY INVOKER・固定search_path・匿名実行不可。原本は管理者のみ読み取り・新規挿入を許す。

2026-09-10 に `qb_image_library_v1` を適用。`tests/image-library.database.sql` の検証データは最後にROLLBACKする。実画像へのOCRや既存問題への画像追加は実施していない。

UIは `index.html` の専用CSSと4本のscript追加で有効化する。既存スクリプトのハンドラを置き換えない。テーブル未作成・設定OFF・非管理者では新規入口が出ない。

停止時は次で新機能の検索・書き込みを止められる。開いている画面の入口表示には再読み込みが必要。

```sql
update public.qb_image_library_config set enabled=false where singleton=true;
```

画面コードの追加だけを戻しても、既存画像とコピーはそのまま使える。データ・bucketのDROPや削除によるロールバックは不要。

検証は `node --test tests/image-library.unit.cjs`、`node tests/image-library.browser.cjs`（Chromium/WebKit）、およびDBのROLLBACK検証。ブラウザ検証は実UI・実保存コードを使い、DB・Auth・Storageだけを合成データにする。GitHub Actionsで既存の最近の画像の回帰テストも実行する。本番への公開にはmainへの取り込みと既存Pages workflowの成功が必要。

追加経路と共通ボタンは `node tests/image-library-add.browser.cjs` で検証する。画面幅・テーマ、クリップボードの許可/拒否、入れ子の画像選択・拡大・キャンセル、書き込み前の版、選択順、独立コピー、取得失敗、本文編集中の貼り付けを確認する。このUI更新ではDB変更や既存画像の一括取り込みは不要。
