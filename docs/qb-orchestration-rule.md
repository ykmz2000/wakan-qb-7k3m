# QB並列作業・オーケストレーション規則

## 権限

ユーザーが複数の独立タスクを与えた場合、オーケストレーターは追加確認なしでサブエージェントへ並列委任できる。この許可は本プロジェクト内で継続する。

## 責任分界

- オーケストレーターは、タスク分解、担当範囲、書込み競合の防止、進捗管理、成果監査、統合、最終検証を担当する。
- サブエージェントの完了報告は監査入力であり、単元完了の根拠にはしない。
- サブエージェントは原則として読取監査と修正文案を並列実行する。同じDB表・同じ問題範囲への書込みはオーケストレーターが直列に統合する。
- 単元完了・科目完了は、統合後の品質ゲートを通したオーケストレーターだけが宣言する。

## 複数単元

複数単元は並列で処理できる。次の項目は単元横断案件としてオーケストレーターへ戻す。

- 共通の解説・修飾ルール
- 共通講義資料と抜粋PDF
- DBスキーマと監査関数
- 単元間の重複問題
- 医学的判断の衝突
- 認証、公開権限、削除などの外部状態変更

単元横断の修正後は、影響する全単元のゲートを再実行する。

## 作業中に届くユーザー指摘

ユーザーは、進行中の位置より前の問題を後追いで指摘する場合も、先の問題を追い越して指摘する場合もある。オーケストレーターは新しい指摘を同じ作業への割込みとして扱う。

- 直ちに是正サイクルを開き、影響する問題・単元・共通ルール・担当エージェントを特定する。
- 関係する担当だけを停止、再指示、再監査し、無関係な並行作業は継続する。
- 指摘前の状態を読んだ監査結果は、現在のDB fingerprintまたは再取得結果と照合する。古ければ統合せず再監査する。
- 先の問題への指摘は作業順から落とさず、該当位置の処理へ予約する。前の問題への指摘は完了扱いを取り消し、修正後にその範囲からゲートを通し直す。
- 最終統合は常に最新のユーザー指示と最新DB状態を基準に行う。
- サブエージェントへ委任したことを理由に、オーケストレーター自身の作業を止めない。独立して進められる修正・統合・次タスクを継続する。
- 新しい指摘で担当範囲が変わった場合、既存サブエージェントへ追加指示または軌道修正を送り、必要なら新しい担当を立てる。
- 結果待ちは、その結果が次の統合に不可欠で、ほかに進められる独立作業がない場合に限る。

## 指摘後の是正

ユーザー指摘または監査失敗があれば、原因究明→改善策作成→即時修正と仕組みへの反映→同じ監査で再検証、の順に処理する。合格しなければ原因究明へ戻り、未完了のまま次の単元へ進まない。

## 訂正文の原文保持

- 原文にない主語や対象名を訂正文へ突然追加しない。省略主語の説明が必要なら選択肢解説で補う。
- 主語・目的語・比較対象・述語・語順を残し、誤っている最小の語または意味単位だけを置換する。
- 数字・頻度・程度だけが誤りなら、その部分だけを直す。`最低5年に1回更新する` は `最低1年に1回更新する` とし、一般化した別表現へ書き換えない。
- 全判定軸を直すために語句を補う場合も、原文の文型と対応関係が追える一文にする。
- 長い問題文は設問指示と症例・定義・引用本文を別段落にする。指示文の終止符直後で改行し、原文の語句は変えない。
- 長い症例・定義・説明本文の末尾に独立した解答指示が続く場合も、指示の直前に実空行を置く。語句・句読点は変えず、短い通常選択式には機械的に適用しない。
- 講義資料に直接根拠がない場合は偽のページを付けず、`該当なし` のレビューを問題内容のfingerprint付きで残す。問題が変わったらレビューを失効させて再照合する。
