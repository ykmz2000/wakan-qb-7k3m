# Unit PDF export

The PDF icon is a sibling of the original unit button, in an unclickable grid row. Only the unit button has `data-u` and the existing navigation handler. PDF events are handled by their own delegated listener and never call practice/detail-loading, rating, or editor functions. Each rerender creates a new row without a persistent observer. Existing unit heading, Coming Soon, and emergency regrouping code moves/hides the whole row. Emergency subset clones carry only that subset's question IDs.

PDF export queries published questions using the existing signed-in Supabase client and RLS. There are no database writes, uploads, new permissions or schema migrations. All export data and canvases are private to the export operation. No editor content, selection, attempts, personal notes or ratings are read or changed. Keyset pagination handles API result limits; questions are grouped by active unit order and study order. Fresh detail batches are checked against the initial unit/publication snapshot. Image read errors abort the entire output rather than omitting images. Closing cancels pending DB reads and prevents late downloads or UI updates.

Output modes are questions, questions with answers, or full explanations (default). Each PDF has an A4 portrait cover; `__all__` additionally has a cover per included unit. Each question starts a fresh page. A section or choice that fits on a page is kept together. Oversized sections begin on a fresh page and split at paragraph/image boundaries, with heading and following content kept together. Paragraphs larger than A4 split by complete lines. Image and caption remain together; images scale without distortion and are never cropped. Question continuation headers identify the same question. Text is rendered at consistent 16px logical / 12pt print size and 3x resolution; formatting uses the original UTF-16 ranges only when source text matches. Page images are embedded in real A4 PDF pages; text is rasterized and is not searchable/selectable in this first version.

The pinned MIT PDF-LIB 1.17.1 browser distribution is vendored with its license. It is loaded only on PDF creation. No build/dependency changes are required for the existing application.

Validation: `node --test tests/unit-pdf-layout.unit.cjs`; `node tests/unit-pdf-export.browser.cjs` with the repository's pinned Playwright client. Browser fixtures use synthetic data and reject all unexpected network traffic and writes. Tests inspect the generated PDF page sizes, covers, ordering, complete images, section boundaries, independent card events, cancellation, retry and original navigation. Existing Pages regression checks remain in place.
